Sundai Hack #133 · Autolab × Maritime

A model that grows
while it learns.

Scaling laws tell you how big to build a model. Nobody asked what shape it should be over time.

github.com/qsimeon/growlab

The unexamined assumption

Chinchilla: given compute C, choose N and D.

It answers that well. But it holds the parameter count N constant for the entire run — and never argued for it. That's not a result. It's just how models are built.

Given compute C, choose the trajectory N(t).
The answer is a shape, not a number.

Why it could work

Training compute is the area under the parameter curve.

Early training learns cheap statistics — token frequencies, basic syntax — that need almost no capacity. Paying for full width from step 0 is buying capacity before you can use it.

Provenance · why the obvious approach dies

Attempt 1: expand a finished model, preserving it exactly.

  "preserve f(x) exactly"
            │
            ▼
  new weights must be ≈ 0
            │
            ▼
  new heads: Q,K ≈ 1e-9
            │
            ▼
  scores = QK/√d ≈ 1e-18
            │
            ▼
  softmax(≈0) = UNIFORM
            │
            ▼
  gradient ≈ 5e-13
            │
            ▼
  dead heads. forever.

Function preservation works perfectly — max logit diff 0.005. And that is exactly what kills it.

No noise scale escapes:
1e-8 → preserved, dead.
1e-4 → alive, preservation destroyed.

The trap exists only because you're expanding something finished and precious.

The reframe

Grow a model that is still mid-training.

Nothing is finished. Nothing is precious. So new parameters get born at real magnitude, gradients flow, and the capacity is actually used.

  grow_width   preservation ABANDONED — new dims ~ N(0, 0.02)
               loss blips 0.02–0.1 nats, absorbed in ~20 steps

  grow_depth   preservation KEPT — new block's output proj = 0
               → exact identity via the residual

  ┌────────────────────────────────────────────────────┐
  │  Zero an OUTPUT projection → safe.                   │
  │    identity via residual, gradient still arrives.  │
  │  Zero an INPUT projection  → fatal.                  │
  │    Q,K = 0 → uniform softmax → dead forever.       │
  └────────────────────────────────────────────────────┘

The inherited code zeroed new width dims — reproducing the softmax barrier inside the direction meant to escape it. That was a bug. We fixed it.

Before trusting any number

We audited the result we started from.

Inherited headline: "same loss at 54% of the FLOPs." Decomposed:

  54.1% FLOPs  =  60.0% (fewer steps)  ×  90.3% (smaller on average)

                  growth was doing 9.7% of the work.
  • n = 1. Every run used seed=42. The "match" was 6.193 vs 6.191 — no error bars.
  • Four things changed at once — growth + WSD + 3.3× LR + warmup.
  • Step counts were hand-tuned per preset until one landed on the target.
  • The vocabulary ate the experiment — see next slide.
Fix that made it measurable

A 50k vocab made growth unable to matter.

The tied embed/lm_head matmul scales linearly in d. The transformer body — the only thing growth shrinks — scales as d². Body wins only when d > V/(12L).

  V = 50,304, L = 6  →  need d > 700.   Experiments ran at d = 128→256.

    d=128  ┌────────────────────────────────┐
           │████████████████████████████░░░░│  embed 91% · body 9%
           └────────────────────────────────┘
                                     ▲ growth can only touch this sliver

  V = 4,096, L = 6   →  need d > 57.  ✓

    d=256  ┌────────────────────────────────┐
           │██████░░░░░░░░░░░░░░░░░░░░░░░░░░│  embed 20% · body 80%
           └────────────────────────────────┘

So we trained a 4,096-token BPE over WikiText-103. Now N(t) genuinely drives the compute bill — and the experiment can detect an effect at all.

The second finding

Growth buys learning-rate robustness, not just compute.

Flat's seed spread is 102× larger (σ 0.532 → 0.053). At this learning rate, starting at full size is unstable and starting small is not. The model is tiny exactly when a high LR would otherwise blow it up.

Growth is acting as a curriculum.

The confound we name ourselves: LR=1e-3 was inherited from the grown preset, so the flat arm runs at an LR it was never tuned for. An LR sweep on flat is the honest next experiment. We didn't run it.

Six hand-run points is not a search

So we gave the search to an agent.

When to grow × how much × width vs depth × how to init × optimizer state × LR around each event. The space is far too big to hand-tune. Autolab's agent proposes, runs, scores and merges growth schedules autonomously.

What the agent learned

Growth timing matters more than growth granularity.

  • Both timing extremes lose — front-loading (4.220) and delaying (4.142).
  • Width-first ordering is worse (4.090) than interleaving width with depth.
  • More, finer growth events do not help (4.112) — it's a flat basin, seed-noise dominated.
  • The optimum is a plateau around completing growth at step 800–950, not a knife edge.

It then stopped and told us it had converged — "remaining variation is seed noise" — and asked whether to raise the seed count. That's the agent knowing the difference between signal and noise.

Honest limits

What we did not show.

  • Scale. 5.9M params, 4k vocab, ~2900 steps. Nothing here survives a serious scale test yet.
  • The LR confound. Flat ran at an LR tuned for grown. A flat-arm LR sweep is the next experiment.
  • n = 3. Better than the n=1 we inherited, but complete separation at 3v3 is p=0.05 — the floor, not a comfortable margin.
  • Open-loop schedules. Growth fires on fixed steps. It should fire when the loss says capacity is saturated.

The negative result would also have been publishable. We built the demo so it works either way — watching an agent search trajectory space is the point.
